METHODS & INTERPRETATION

Know what you’re looking at.

An exploratory workspace, with the data’s limits kept visible.

What is a candidate site?

A candidate is a transcript position for which direct RNA sequencing signal measurements are available. Several RNA molecules, represented by reads, can cover the same position.

Coverage counts those reads at the site. It does not determine whether the RNA is modified.

What does a score mean?

After you import model output, the score describes the model’s estimate for a site. A score of 0.8 does not mean that 80% of its reads are modified.

Scores may require probability calibration. A chosen cutoff is an exploration setting, not evidence of experimental confirmation.

How are samples compared?

Samples are joined only on the same transcript ID and transcript position, after the coverage filter. A common reference annotation is required. Sites across different isoforms are not merged.

Missing measurements are kept distinct from low scores. Separate sequencing runs from biological replicates, and examine replicate consistency before attributing differences to a cell line.

What is loaded today?

Three development datasets supplied in this project are loaded with real site IDs, sequence context and coverage. Dataset 0 is the Hct116 training dataset described in the project brief; cell lines are not specified for datasets 1 and 2.

Gene IDs for dataset 0 come from its supplied labels. Dataset 1 annotations are matched to that metadata by transcript ID where possible. No gene names are invented.

Dataset 2 uses anonymised transcript IDs and contains intermediate label values. Those values are shown as provided labels in site details, and are not treated as prediction scores or automatically interpreted as modification fractions.

Why are SG-NEx runs marked not loaded?

The catalogue records the 23 processed sample folders from your AWS listing. Their raw data is on your AWS machine and has not been imported into this platform.

Prepare a sample for import

  1. Download export_coverage.py and put it on your AWS machine.
  2. Run it against the processed JSON, using the actual paths:
python3 export_coverage.py \
  --input /path/to/data.json \
  --sample SGNex_A549_directRNA_replicate6_run1 \
  --output A549_rep6_run1_coverage.csv

The helper supports .json and .json.gz and needs no additional Python packages. It checks read dimensions and finite values, counts reads at each site and leaves the original JSON intact.

Transfer the coverage CSV to your computer, then import it here. Model predictions can be attached later.
