Methods & practical guide

Open a section when you need more detail.

Understanding sites and scoresCandidate sites, read coverage and interpretation＋

What is a candidate site?

A candidate is a position within a transcript with direct RNA sequencing signal measurements. Coverage counts the reads spanning that position; it does not determine whether the site is modified.

What does the score mean?

Dolly scores describe the model’s estimate for a site. A score of 0.8 does not mean that 80% of its reads are modified. On held-out labels (dataset1 genes the model never saw), scores up to about 0.5 behave like probabilities. Above 0.5, about half of called sites carry a label whatever the score, so 0.9 does not mean 90% confidence. See How much should I trust a score? in the Overview. A chosen cutoff is an exploration setting.

Use this workspace for exploration and hypothesis generation. Score differences alone do not establish biological changes in m6A.

Data and filtering23 SG-NEx runs, cell-line summaries and missing values＋

Dolly v2 predictions cover 23 SG-NEx direct RNA-sequencing runs across A549, H9, HEYA8, Hct116, HepG2, K562 and MCF7. These unlabelled runs support exploratory comparisons, not an accuracy evaluation. The model was trained on Hct116 data.

Coverage and summaries

Supplied SG-NEx score records have at least 20 reads per site. Detailed records load when needed; processed signal inputs are not bundled into the website.

Derived cell-line summaries retain sites with a mean score of at least 0.5 in one or more cell lines. They are a selected subset, not all measured sites. Missing values are excluded rather than treated as zero.

Which filters affect which views?

Overview sample and coverage filters control its charts. The exploration cutoff changes the high-scoring percentage plot, not the score-distribution histogram. In Site explorer, Minimum table score and Scored sites only affect Exact measurements; transcript plots retain lower scores for comparison.

Comparison methodsSite matching, score differences and replicate consistency＋

Samples are matched using the same transcript ID and transcript position after coverage filtering. Use a common reference annotation. Sites in different transcript isoforms are not merged.

Comparing cell-line pairs

Mean absolute score difference averages the absolute score gaps at shared sites. Smaller values indicate more similar predicted scores on those sites, not necessarily more similar biology.

Use the same set of sites across all selected cell lines when ranking pairs. Pair-specific shared sets can provide more coverage, but their distances may reflect different site sets.

Check individual runs

Distinguish sequencing runs from biological replicates. Inspect coverage and consistency across runs before interpreting differences between cell lines.

Known limitationsOne affected run, the training cell line, technical replicates and what the data cannot show＋

MCF7 replicate 3 · run 1 was scored without transcript-structure features

This is the only run whose transcript IDs carry a version suffix (for example ENST00000303577.7). Dolly v2 looks up each transcript in the Ensembl 91 annotation by exact ID, so it found no annotation for any of this run's 109,315 sites. It scored them all with its fallback model, which is equivalent to v1 and has no transcript-structure features. The coordinates are correct: at the 88,680 sites shared with MCF7 rep 4 the 7-mer matches in 100% of cases. The scores, however, come from a different model and are not comparable with the other runs (rank correlation with MCF7 rep 4 is 0.76, against about 0.93 for other same-cell-line pairs).

What this website does: the run is kept and shown with a hollow, dashed marker and a warning badge. It is left out of every cell-line summary, mean, shared-site set, reproducibility statistic, Landscape view and atlas, so the MCF7 summary is based on one run (rep 4). Its own sites can still be opened in Site explorer by choosing the run.

One useful by-product: because this run was scored without position features, it shows that the stop-codon enrichment and exon-junction depletion are in the nanopore signal, not only in v2's features.

Hct116 is the training cell line

The model was trained only on Hct116 data. On sites measured in all seven lines, Hct116 calls about 20% more sites than the other six lines, in all three of its runs and for every motif. Held-out labels show no Hct116 accuracy advantage, so this is most likely a calibration shift towards the training line, not more m6A. Hct116 rep 3 · run 1 may share reads with the training data: on training-labelled sites it scores far higher than the other Hct116 runs (PR AUC 0.88 vs 0.71). Treat its scores on training genes as in-sample.

Runs are technical, not biological replicates

Re-sequencing the same library agrees as well as a new replicate does, so these runs cannot estimate biological variability. Cell-line differences are smaller than run-to-run noise (2% vs 4% of score variance). A permutation test (50 label shuffles) puts the false discovery rate of "cell-line-specific" sites at about 30–40% for differences of 0.3–0.4 in mean score, and 53% for differences of 0.2.

Other limits

  • Scores are rankings, not modification fractions; precision levels off at about 50% above a score of 0.5.
  • Sites are in transcript coordinates; the same genomic adenosine on two isoforms appears twice, which inflates gene-level counts.
  • Gene symbols come from the Ensembl 91 annotation; gene and transcript IDs remain the matching keys.
  • The m6Anet comparison shows summary results from experiment 12; per-site m6Anet scores are on the team's AWS machine.
  • Only DRACH motifs are candidate sites, and only sites with at least 20 reads in a run are scored.

Prepare a sample for import

  1. Download export_coverage.py and put it on your AWS machine.
  2. Run it against the processed JSON, using the actual paths:
python3 export_coverage.py \
  --input /path/to/data.json \
  --sample SGNex_A549_directRNA_replicate6_run1 \
  --output A549_rep6_run1_coverage.csv

The helper supports .json and .json.gz and needs no additional Python packages. It checks read dimensions and finite values, counts reads at each site and leaves the original JSON intact.

Transfer the coverage CSV to your computer, then import it here. Model predictions can be attached later.
